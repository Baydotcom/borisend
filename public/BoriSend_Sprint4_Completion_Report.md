## 6. DeviceService Implementation Summary

**File:** `src/services/mobile/DeviceService.js`

### Changes Made

Replaced placeholder `return { not_implemented }` stubs with real Capacitor Device plugin calls. Added lazy-loaded plugin accessors (`_getDevicePlugin`, `_getAppPlugin`) that dynamically import `@capacitor/device` and `@capacitor/app` only when called on native platforms.

### Native Implementation

**`getDeviceInfo()` — Native path:**
1. Calls `PlatformService.isNative()` to check platform
2. Lazy-imports `@capacitor/device` plugin
3. Calls `Device.getInfo()` → returns `{ platform, model, osVersion, manufacturer }`
4. On error: logs and falls back to web implementation

**`getAppInfo()` — Native path:**
1. Calls `PlatformService.isNative()` to check platform
2. Lazy-imports `@capacitor/app` plugin
3. Calls `App.getInfo()` → returns `{ version, build }`
4. On error: logs and falls back to web implementation

### Web/PWA Fallback (Preserved)

| Method | Web Return |
|---|---|
| `getDeviceInfo()` | `{ platform: "web", model: <browser>, osVersion: <userAgent>, manufacturer: "Web" }` |
| `getAppInfo()` | `{ version: "web", build: "web" }` |
| `getBatteryLevel()` | Uses `navigator.getBattery()` API |
| `getLanguage()` | Uses `navigator.language` |

### Public Interface

**Unchanged.** Same method signatures: `getDeviceInfo()`, `getAppInfo()`, `getBatteryLevel()`, `getLanguage()`.

## 7. LifecycleService Implementation Summary

**File:** `src/services/mobile/LifecycleService.js`

### Changes Made

Replaced direct `window.Capacitor.Plugins.App` access with the installed `@capacitor/app` plugin, loaded via lazy dynamic import. The native lifecycle listeners are now wired through the official Capacitor App plugin instead of the raw bridge.

### Native Events Connected

| Event | Capacitor Plugin Method | LifecycleService Event |
|---|---|---|
| App state change (foreground) | `App.addListener('appStateChange', { isActive: true })` | `resume` |
| App state change (background) | `App.addListener('appStateChange', { isActive: false })` | `background` |
| URL scheme open | `App.addListener('appUrlOpen', { url })` | `deepLinkOpened` |
| Hardware back button | `App.addListener('backButton', ...)` | (no-op, lets app handle) |

### Web Lifecycle Events (Preserved)

| Event | DOM API | LifecycleService Event |
|---|---|---|
| Page visibility | `document.visibilitychange` | `resume` / `background` |
| Window focus | `window.focus` | `resume` |
| Window blur | `window.blur` | `background` |
| Network online | `window.online` | `networkRestored` |
| Page hide | `window.pagehide` | `background` / `terminate` |
| App launch | (on init) | `launch` |

### Initialization Flow

1. `LifecycleService.init()` called once by `DeepLinkHandler` component
2. `_initialized` guard prevents double-init
3. Web DOM listeners registered immediately
4. If native: `_getAppPlugin()` dynamically imports `@capacitor/app`, then registers native listeners
5. All callbacks wrapped in try/catch for error isolation

### Public Interface

**Unchanged.** Same methods: `init()`, `on(event, callback)`, `emitNotificationOpened(payload)`, `emitDeepLinkOpened(url)`.

## 8. DeepLinkService Implementation Summary

**File:** `src/services/mobile/DeepLinkService.js`

### Changes Made

**No changes required.** The DeepLinkService was already fully implemented in Sprint 3 and correctly handles all 4 route types. The native `appUrlOpen` events are now properly wired through the Capacitor App plugin (via LifecycleService), which emits `deepLinkOpened` events that `DeepLinkHandler` component routes to `DeepLinkService.handle()`.

### Route Mapping (Unchanged)

| Deep Link | In-App Route |
|---|---|
| `borisend://message/{id}` | `/messages/{id}` |
| `borisend://communication-plan/{id}` | `/campaigns/{id}` |
| `borisend://notification/{id}` | `/notifications?id={id}` |
| `borisend://subscription` | `/subscription` |

### End-to-End Flow

1. Native app opened via URL scheme → Capacitor `App.addListener('appUrlOpen')`
2. LifecycleService receives `{ url }` → emits `deepLinkOpened`
3. `DeepLinkHandler` component receives event → calls `DeepLinkService.handle(url)`
4. `DeepLinkService.parse(url)` extracts type + id → returns `{ route, type, id }`
5. `DeepLinkHandler` calls `navigate(parsed.route)` → React Router navigates

### Public Interface

**Unchanged.** Same methods: `parse(url)`, `register(handler)`, `handle(url)`, `build(type, id)`, `buildNotificationPayload(type, id, extra)`.

## 9. Router Compatibility Summary

**File:** `src/App.jsx`

### Changes Made

**No changes required.** The existing `BrowserRouter` is compatible with Capacitor's native WebView when `server.androidScheme` and `server.iosScheme` are set to `'https'` in `capacitor.config.ts`.

### Why BrowserRouter Works

Capacitor 6 serves the web bundle from the local filesystem using the configured scheme (`https://localhost` on Android, `capacitor://localhost` on iOS). With `androidScheme: 'https'` and `iosScheme: 'https'`, the WebView treats all routes as same-origin HTTPS paths, allowing `BrowserRouter` to handle client-side routing without server-side fallback.

No switch to `HashRouter` was needed. All existing routes, navigation, `<Link>` components, and `ScrollToTop` continue to work identically on web, PWA, Android, and iOS.

## 13. Known Issues

### 1. Native Project Generation Requires Local Execution

The `android/` and `ios/` native project directories cannot be generated in the cloud environment. The configuration is complete and ready — `npx cap add android` and `npx cap add ios` must be run locally with the respective SDKs installed.

### 2. Google OAuth Redirect URI

When the app runs natively, Google OAuth redirects must include the Capacitor scheme. The Google OAuth console needs a redirect URI like `com.borisend.app://oauth` (or `https://localhost` depending on configuration). This is a configuration step, not a code change — the existing `loginWithProvider('google')` call in the auth pages will work once the redirect URI is registered.

### 3. Push Notification Delivery Deferred

`@capacitor/push-notifications` is installed but `NotificationService.registerForPush()` still returns `{ success: false, error: "not_implemented" }`. Per sprint requirements, push delivery is not implemented in Sprint 4. The plugin is installed and ready for Sprint 5 wiring. No code changes will be needed to the service interface — only the internal implementation of `registerForPush()`.

### 4. `allowMixedContent: true` on Android

This allows the WebView to load mixed content (HTTP resources on HTTPS pages). This is needed because some external resources may not support HTTPS. It should be reviewed before production release and disabled if all resources support HTTPS.

### 5. Dynamic Imports for Plugin Loading

DeviceService and LifecycleService use dynamic `import()` to load Capacitor plugins lazily. This prevents the plugins from being loaded on web/PWA (where they'd be unused), keeping the web bundle size unchanged. The imports are wrapped in try/catch so a failed import never crashes the app — it falls back to the web implementation.
